# =======================================

# 1. Introduction to React

# =======================================

React is a JavaScript library used to build user interfaces.

Simple meaning:

→ JavaScript gives us programming power
→ React helps us build and manage UI

React is especially useful for interactive websites and web applications.

Examples:

* Shopping websites
* Dashboards
* Social media apps
* Todo apps
* Admin panels
* Myntra-like websites

React's main idea:

→ Break a big UI into small reusable components.

Example:

Myntra

```
Header
Navbar
ProductList
    ProductCard
    ProductCard
    ProductCard
Footer
```

Instead of writing one huge file, we divide the UI into manageable pieces.

Explanation:

React → JavaScript library for building UI

Component → reusable piece of UI

# =======================================

# 2. Why React?

# =======================================

Imagine a large website.

Without components, the code can become very difficult to manage.

React lets us divide the website into components.

Example:

```
Header
Product
Button
Footer
Cart
```

Each component can have its own logic and UI.

Main benefits:

* Reusable components
* Easier code management
* Interactive UI
* State management
* Routing
* Large application support

Simple story:

Instead of building one huge house,

we build:

```
Room
Door
Window
Kitchen
Bathroom
```

Then combine them.

React does something similar with UI.

# =======================================

# 4. JSX

# =======================================

JSX allows us to write HTML-like code inside JavaScript.

Example:

function App() {
return <h1>Hello React</h1>;
}

This looks like HTML,

but it is written inside JavaScript.

JSX can also use JavaScript values.

Example:

const name = "Ali";

function App() {
return <h1>Hello {name}</h1>;
}

Output:

Hello Ali

Explanation:

{} → lets us use JavaScript expressions inside JSX.

Example:

<h1>{name}</h1>

React sees:

name → JavaScript variable

# =======================================

# 5. JSX Rules

# =======================================

JSX looks like HTML but has some differences.

Example:

HTML:

<div class="box"></div>

JSX:

<div className="box"></div>

Important:

class → className

for → htmlFor

JavaScript expressions go inside:

{}

Example:

const price = 500;

<p>Price: {price}</p>

JSX should return one parent structure.

Example:

<> <h1>Hello</h1> <p>Welcome</p>
</>

The empty tags are called Fragment.

# =======================================

# 6. Fragment

# =======================================

Sometimes we don't want to add an extra div.

Instead:

<> <h1>Hello</h1> <p>Welcome</p>
</>

This is a Fragment.

It groups elements without adding an extra DOM element.

Explanation:

Fragment → group elements without unnecessary HTML element.

# =======================================

# 7. Props

# =======================================

Props means properties.

Props are used to send data from a parent component to a child component.

Example:

<Product name="Nike Shoes" price={5000} />

Here:

name → "Nike Shoes"

price → 5000

The Product component receives these values.

function Product(props) {
return ( <div> <h2>{props.name}</h2> <p>{props.price}</p> </div>
);
}

Simple story:

Parent has data.

Parent sends data.

Child receives data.

```
Parent
   ↓
 Props
   ↓
 Child
```

Explanation:

Props → data sent from parent to child.

# =======================================

# 8. Props Destructuring

# =======================================

Instead of:

function Product(props) {
return <h2>{props.name}</h2>;
}

We can destructure:

function Product({ name, price }) {
return ( <div> <h2>{name}</h2> <p>{price}</p> </div>
);
}

This is shorter and easier to read.

# =======================================

# 9. Props are Read-Only

# =======================================

A child component should not directly change its props.

Example:

<Product name="Nike" />

The child receives:

name = "Nike"

The child should use the value, not directly modify the prop.

If data needs to change:

→ use state
→ or ask the parent to change it through a function

Sometimes we want to put content inside a component.

Example:

<Container>
    <h1>Hello</h1>
</Container>

The content inside Container becomes:

children

Container:

function Container({ children }) {
return ( <div className="container">
{children} </div>

Simple meaning:

children → whatever content is placed inside the component.

Example:

<Card>
    <h2>Nike Shoes</h2>
    <p>Price: Rs 5000</p>
</Card>

The Card component receives both elements as children.

Why use it?

Because it makes wrapper components reusable.

The same Container can contain:

→ heading
→ product
→ form
→ image
→ another component

# =======================================

# 11. State

# =======================================

State is data that can change inside a component.

Example:

Cart count:

```
Cart: 0
```

User clicks Add:

```
Cart: 1
```

Clicks again:

```
Cart: 2
```

This changing value is state.

Simple meaning:

State → component's changing memory.

Example:

const [count, setCount] = useState(0);

count → current value

setCount → function used to change it

0 → initial value

# =======================================

# 12. useState

# =======================================

useState is a React Hook used to create state.

Import:

import { useState } from "react";

Example:

const [count, setCount] = useState(0);

Change value:

setCount(10);

Do not normally do:

count = 10;

Instead:

setCount(10);

Why?

Because React needs to know that the state changed so it can update the UI.

Story:

```
State changes
     ↓
React knows
     ↓
UI updates
```

# =======================================

# 13. State Example

# =======================================

import { useState } from "react";

function App() {

```
const [count, setCount] = useState(0);

return (
    <div>
        <h1>{count}</h1>

        <button onClick={() => setCount(count + 1)}>
            Add
        </button>
    </div>
);
```

}

When button is clicked:

count changes

0 → 1

1 → 2

2 → 3

React updates the UI.

# 14. Event Handling

# =======================================

Events are actions performed by the user.

Examples:

* Click
* Type
* Submit
* Mouse enter
* Keyboard press

React handles events using event props.

Example:

<button onClick={handleClick}>
    Click
</button>

Function:

function handleClick() {
console.log("Clicked");
}

Common events:

onClick
→ button click

onChange
→ input value changes

onSubmit
→ form submitted

onMouseEnter
→ mouse enters element

onKeyDown
→ keyboard key pressed

# =======================================

# 15. Important Event Difference

# =======================================

Correct:

<button onClick={handleClick}>
    Click
</button>

Usually wrong:

<button onClick={handleClick()}>
    Click
</button>

Why?

handleClick

→ gives React the function

handleClick()

→ immediately calls the function

If arguments are required:

<button onClick={() => handleClick("Ali")}>
Click </button>

# =======================================

Conditional rendering means:

Example:

{isLoggedIn ? <Dashboard /> : <Login />}

If true:

Dashboard

If false:

Login

Another example:

This means:

If isLoggedIn is true → show Dashboard.

# =======================================

Condition:

Simple meaning:

# =======================================

Suppose we have products:

     key={product.id}
     product={product}
 />

map()

→ goes through every item

# =======================================

# 22. key in React

# =======================================

When rendering lists, React needs a unique key.

Example:

products.map(product => ( <Product
     key={product.id}
     product={product}
 />
))

key helps React identify each item.

Best:

key={product.id}

Avoid using array index when a proper unique ID is available.

Explanation:

key → tells React which list item is which.

# =======================================

Sometimes two child components need the same data.

Example:

```
    Parent
    State
    /   \
   ↓     ↓
Input   Display
```

Instead of keeping separate state in both children:

→ move state to their common parent.

This is called:

Lifting State Up

Simple meaning:

Move shared state to the nearest common parent.

# =======================================

# 25. One-Way Data Flow

# =======================================

React normally follows one-way data flow.

```
Parent
   ↓
 Props
   ↓
Child
```

Data normally moves from parent to child.

If child needs to affect parent:

→ parent passes a function to child.

This makes data flow easier to understand.

# 29. useEffect Cleanup

# =======================================

Some effects create things that need to be stopped.

Example:

Timer.

useEffect(() => {

```

    console.log("Hello");

return () => {
    clearInterval(timer);
};
```

}, []);

The returned function is cleanup.

Why?

Because when the component no longer needs the timer:

→ stop the timer.

Common cleanup examples:

* clearInterval
* removeEventListener
* unsubscribe from subscriptions

# 30. useRef

# =======================================

useRef is used to keep a value/reference without causing a re-render when the ref value changes.

Common use:

→ Access DOM elements

Example:

import { useRef } from "react";

function App() {

```
const inputRef = useRef(null);

function focusInput() {
    inputRef.current.focus();
}

return (
    <div>
        <input ref={inputRef} />

        <button onClick={focusInput}>
            Focus
        </button>
    </div>
);
```

}

When button is clicked:

→ input gets focus.

Simple difference:

useState

→ changing state causes re-render

useRef

→ changing ref does not cause re-render

# 53. React.memo

# =======================================

React.memo can prevent unnecessary re-rendering of a component when its props have not changed.

Example:

Simple meaning:

If the component receives the same props,

React may reuse the previous rendered result instead of unnecessarily rendering it again.

Do not use memo everywhere.

Use it when performance optimization is actually useful.

# =======================================

# 57. Re-render

# =======================================

When relevant state, props, or context changes, React may render the component again.

Example:

count = 0

User clicks button.

setCount(1)

State changed.

React updates the UI.

Important:

Re-render does NOT mean the browser completely reloads the page.

React updates the necessary UI.

# =======================================

# 58. Virtual DOM

# =======================================

React uses an internal representation of the UI.

When state changes:

→ React determines what needs to change

→ React updates the necessary DOM parts.

Simple idea:

Instead of thinking:

"Refresh the whole page."

Think:

"React figures out which UI needs updating."

# =======================================

# 59. Reconciliation

# =======================================

Reconciliation is the process React uses to determine what changed between renders and what needs to be updated.

Example:

```

```

After:

```
Product price = 600
```

React determines that the relevant UI changed.

Then the required DOM update can happen.

This is one reason beginners sometimes see:

"My effect is running twice!"

Development StrictMode checks should not be confused with production behavior.

# 61. Component Lifecycle

# =======================================

A component can be thought of as having stages:

```
Mount
  ↓
Update
  ↓
Unmount
```

Mount:

→ component appears

Update:

→ state/props/context change

Unmount:

→ component is removed

useEffect cleanup is especially important when a component is unmounted or when an effect needs to be replaced because dependencies changed.

# =======================================

# 62. Hooks

# =======================================

Hooks are React functions that let function components use React features.

Important hooks:

useState

→ state

useEffect

→ side effects / external synchronization

useRef

→ refs / values without re-render

useContext

→ context

useReducer

→ complex state logic

useMemo

→ memoized value

useCallback

→ memoized function

# =======================================

# 63. Rules of Hooks

# =======================================

Hooks should normally be called:

→ at the top level of a component or custom hook.

Do not put hooks inside:

* if statements
* loops
* nested functions

Wrong:

if (loggedIn) {
const [user, setUser] = useState(null);
}

Correct:

const [user, setUser] = useState(null);

# 66. Environment Variables

# =======================================

Environment variables can store configuration values.

With Vite, client-side variables commonly use:

VITE_

Example:

VITE_API_URL

Access:

import.meta.env.VITE_API_URL

Important:

Frontend environment variables are not automatically secret.

If the value reaches the browser, users can inspect it.

Do not put real secrets in frontend code.

# =======================================

# 75. Final React Learning Advice

# =======================================

Do not try to memorize every React definition.

For every topic, ask three questions:

1. What problem does it solve?
2. When do I use it?
3. Can I write a small example myself?

Example:

useState

Problem:

→ UI needs changing data.

Use when:

→ component has data that changes.

Practice:

→ Counter.

useEffect

Problem:

→ component needs to synchronize with something outside normal rendering.

Use when:

→ API request, timer, event listener, etc.

Practice:

→ Fetch products.

Props

Problem:

→ child needs data from parent.

Use when:

→ passing product/user/data.

Practice:

→ ProductCard.

Router

Problem:

→ application needs different URLs/pages.

Use when:

→ Home, Men, Women, Bag, Profile.

Practice:

→ Myntra navigation.

Redux

Problem:

→ complex shared application state.

Use when:

→ many components need shared state.

Practice:

→ Myntra cart.
